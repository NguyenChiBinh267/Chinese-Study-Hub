# Temporary cloud gate proof

Synthetic transactions only. No learning content, answer keys, reviewer packets or local history. Auth-protected routes use remotely verified owner identity and the existing application transaction/RLS helper. Deploy only after actual Free eligibility and cloud security checks; remove the temporary deployment after bounded measurements. No T053 release.

Run `npm ci`, `npm run test:security`, and `npm run build`. Server-only configuration: CSH_PROOF_MODE=cloud-benchmark-v1, CSH_PROJECT_REF, CSH_POOLER_HOST, CSH_AUTH_URL, CSH_AUTH_PUBLISHABLE_KEY, OWNER_USER_ID, DATABASE_URL (custom runtime role, sslmode=verify-full), CSH_DATABASE_CA_PEM (pinned provider certificate), CSH_PROOF_COMMIT (exact tested source), and CSH_APP_ORIGIN (canonical HTTPS proof origin). Never provide admin or service-role credentials to the app.

The manual `node scripts/benchmark-cloud-proof.mjs --measure` requires matching ignored cloud-gate account/config/benchmark-target files from the authorized bootstrap; it performs only five fresh-client and twenty warm measurements. `npm run test:host:browser` uses the same ignored target/account files and requires an installed Playwright Chromium. Never publish these credential files. Cleanup removes the exact synthetic nonowner and proof cohort; a later authorized rerun must recreate that user through the supported bootstrap, recreate a disposable Hobby project, and configure server environment values through CLI stdin. No security-protection bypass or real learning deployment is authorized. See docs/cloud-gates/verification-report.md and hosting-results.json for measured results and billing limitations.
