# Master Plan in Git — authority and provenance

This directory is a migration candidate in draft PR #3. It becomes official only after owner review and merge to verified origin/main. The engine currently blocks SOURCE because main lacks the artifacts; it never substitutes a workspace cache. The original Google Doc was read/exported without modification. After migration it is a read-only historical reference, with no runtime API/OAuth dependency.

- master-plan-v1.1.md: canonical specification, with original product/ADRs/data/learning/UX/security/rights/roadmap/tasks preserved.
- task-status.json: the only mutable task-status authority. Only the controller updates one task after verified completion. Initial T001/T002 notes are historical import evidence, not new execution.
- source-export-v1.1.md: untouched official Markdown export; immutable provenance/reference, not a live status store.
- source-manifest.json: original URL/revision/import time, SHA256 and explicit transforms/activation rule.
- native-paragraph-validation.json and migration-report.json: independent native-reader paragraph/link comparison plus import/dependency checks.

The derived task index exists in memory and is validated from canonical specification/status at a pinned Git commit. The old index and handoffs are archived under docs/engineering-loop/history and are never scheduler inputs. Planning prose/change logs in the original document are historical; mutable execution status comes only from JSON. Two original status paragraphs were removed from canonical specification and retained in initial JSON evidence. No ADR/release/task specification was rewritten; only authority metadata and status separation were added.

Validation: 912 nonempty paragraphs matched in sequence after Markdown/NFC/whitespace normalization; 48 linked URLs present; three tables and seven ADRs retained; 70 unique definitions, activation counts 34/14/7/3/3/3/6, no cycle and M0 dependency closure. The comparison uses FNV1a paragraph digests; exact export bytes use SHA256 separately. Layout/comments/revision-history or complete semantic equivalence is not claimed. Run `node tools/engineering-loop/validate-import.mjs` for this migration checkpoint; reimport refuses existing artifacts rather than reset statuses. Future specification changes require a reviewed commit, updated plan hash and explicit source reconciliation; do not rewrite the original snapshot.

Owner evidence for non-automatable facts is read only from the pinned protected path docs/master-plan/owner-evidence/Txxx.json. Missing/expired/unverified evidence blocks acceptance. Receipts must have taskId, verified=true, verifiedBy=owner, relevant scopes, checkedAt/expiresAt, artifactSha256 and evidenceUrls. Source verification also requires matching sourceRecords URL/hash; official exam format needs separate exam-blueprint approval. Final document approvals bind the actual file hash; model-created declarations do not count. Account-zero-cost receipts additionally require actual accountTier/quotas, billingDisabled=true, oneTimeFees=0, recurringFees=0 and noTrialCredits=true.

Those receipts are evidence supplied and reviewed by the human owner, not automatic verification of account/legal/language facts. Never fabricate true values or store secrets/private account details. No receipts are created in this upgrade. Adding proof/specification on main during a run causes drift and requires explicit reconciliation/rebase/review; an unattended human approval/reconciliation lane is not implemented. T004/T005/T068 policies are prepared contracts, not authorized execution or proven real-task acceptance.

Status completion records carry run/task, PR URL, reviewed SHA, merge SHA, pinned source/spec hash, checks, verdict and timestamp. The controller verifies exact two-parent merge ancestry, only this JSON path in status commit, unchanged other tasks/specifications, and exact remote HEAD/blob readback. Failed status push resumes SSOT_WAIT with the pending commit; implementation/merge are not repeated. Non-force push rejects concurrent main changes. No auto-merge or real status writes are enabled by this migration.
