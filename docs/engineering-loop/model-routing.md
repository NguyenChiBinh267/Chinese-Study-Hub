# Adaptive model routing and quota protection

Routing extends runCodex/codexArguments; it does not replace the controller. Classification is deterministic from controller-verified task specification and file scope, never from developer COMPLETE, repair findings or prompt instructions. Small docs/JSON/CSS/UI scopes use gpt-6-luna/low; ordinary development uses Luna/medium. Complex/security/auth/RLS/concurrency/Git/SSOT/control-plane work uses gpt-6.1-sol/medium. Reviewers use Luna/medium or Sol/high for high risk. Escalation is off by default; a policy-authorized higher model requires a recorded reason, remaining escalation/call budget, authenticated model support and selected-model quota. Astra is never an automatic default or fallback.

Every exec explicitly pins --model and model_reasoning_effort while preserving --ignore-user-config, --ephemeral, reviewer read-only sandbox, ChatGPT-only auth and stripped API credentials. Authenticated metadata-only CLI RPCs read account type, paginated model/list and account/rateLimits/read; they never start a thread/turn or inference. The API model catalogue is not used. Missing/hidden/unavailable models or unsupported reasoning efforts block before dispatch; no alias, downgrade or paid fallback is inferred.

Current verification (2026-10-16 Asia/Saigon): codex-cli 0.153.4 under the existing ChatGPT login advertises gpt-6-astra, gpt-5.6-sol, gpt-5.6-terra and gpt-5.6-luna. It does not advertise either requested gpt-6-luna or gpt-6.1-sol. Its quota metadata contains only an unbound codex bucket. Therefore current real dispatch is BLOCKED; desktop/API model lists are not treated as evidence that the CLI can use these models. No inference-based availability check was performed or is claimed.

Quota reserve defaults to 20 percent and cannot be configured below 20. Every reported selected-model/global window must have known usage, duration and future reset time, known-zero credit eligibility and an unblocked spend-control state. The CLI must explicitly associate a quota bucket with the selected model (model, normalModelSlug or an exact models array); generic codex quota alone is insufficient. Operator config cannot invent that association. Account diagnostic freeQuota output is marked modelQuotaVerified=false and cannot admit a model call. Post-call snapshots are recorded and reserve exhaustion/unreliable metadata blocks result acceptance. Preflight/postflight checks cannot guarantee a long in-flight call will never cross the reserve; no token-cost prediction or such guarantee is claimed.

Defaults in modelRouting: maxCallsPerTask=6, maxDeveloperCalls=3, maxReviewerCalls=3, maxEscalationsPerTask=0, allowEscalation=false, allowAstra=false, syntheticProofAuthorization=null. Task-specific settings can lower call caps or raise the reserve; all limits are bounded. At most two repair indices are accepted. A reserve/cap/missing-evidence failure never dispatches a replacement model. Synthetic CLI proofs are disabled unless an explicit expiring proof ID is configured; its persistent shared counter caps the entire proof at at most eight calls, across synthetic task IDs. This validation does not grant such authorization.

Per-task model budgets live in ignored .engineering-loop/model-budgets. A task uses its stable execution identity; bootstrap uses pinned repository/PR/base rather than transient run/nonce, so restarting bootstrap cannot refund calls. Counts are reserved durably under a lock before dispatch. Failed/interrupted calls are never refunded. Repeating the same role/HEAD/contract/policy invocation is blocked; one separately authorized escalation can use its distinct model key within the escalation cap. Existing persistent grant budgets and Git/status controls remain separate additional constraints, not replaced by this journal.

First review inspects the task diff and relevant callers/acceptance inputs, not an unbounded repository audit. Repair review uses a narrowed delta only when previous independent read-only REWORK, source base, contract/policy hashes, report digest, unchanged snapshot fingerprint and ancestor SHA are all verified. It passes the bound previous findings to a fresh independent reviewer; all deterministic checks still run on current HEAD and no verdict is copied. Changed contract/source/policy requires task-scope review again. A previous BLOCKED response does not qualify for delta reuse.

Receipts record task/role, requested and actually reported model, requested/observed reasoning, call/repair/escalation counters, routing reason, token input/cached/output/total when emitted, and quota before/after. Cached tokens are included within input and are not added twice. Supported turn.completed events are accumulated with turn-ID deduplication; cumulative token_count totals are a fallback, never added again. Missing usage stays null. Model identity missing/mismatched or an unapproved server reroute blocks; requested CLI arguments are never mislabeled as actual model evidence. Raw tool/model text, OAuth credentials, reset-credit IDs and account details are not logged.
