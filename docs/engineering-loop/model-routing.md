# Adaptive model routing and quota protection

Routing extends runCodex/codexArguments; it does not replace the controller. Classification is deterministic from controller-verified task specification and file scope, never from developer COMPLETE, repair findings or prompt instructions. Exact IDs are resolved from the current authenticated CLI catalogue, with the requested reasoning effort advertised. Light/ordinary work uses the first available policy family in Luna, Terra, Sol order (low for small docs/JSON/CSS/UI developer work, medium otherwise). Architecture/complex debugging/security/auth/RLS/concurrency/Git/SSOT/control-plane work requires Sol (developer medium, reviewer high). No version is hardcoded. Multiple eligible versions in the same family, unknown families or missing strong models block rather than guessing a capability/price ranking. Family order is a conservative policy assumption, not measured token savings or pricing metadata. Astra is never an automatic default or fallback.

Every exec explicitly pins --model and model_reasoning_effort while preserving --ignore-user-config, --ephemeral, reviewer read-only sandbox, ChatGPT-only auth and stripped API credentials. Authenticated metadata-only CLI RPCs read account type, paginated model/list and account/rateLimits/read; they never start a thread/turn or inference. The API model catalogue is not used. Missing/hidden/unavailable models or unsupported reasoning efforts block before dispatch; no alias, downgrade or paid fallback is inferred.

Current verification (2026-10-16 Asia/Saigon): codex-cli 0.153.4 under the existing ChatGPT login advertises gpt-6-astra, gpt-5.6-sol, gpt-5.6-terra and gpt-5.6-luna. Current routing therefore resolves light/ordinary tasks to gpt-5.6-luna and high risk to gpt-5.6-sol. The Desktop usage tool and CLI account/rateLimits/read both expose shared codex account windows; neither supplies a per-model allowance here. Desktop model descriptions/session settings are not used to assert CLI support. No inference-based availability check was performed or is claimed. The earlier hardcoded-model/per-model-quota blockage is historical in model-routing-report.json at c892d1c; current metadata/mock readiness is recorded separately in model-routing-readiness.json.

Quota reserve defaults to 20 percent and cannot be configured below 20. Every applicable window must have known usage, duration and future reset time, known-zero credit eligibility and an unblocked spend-control state. An explicit model association (model, normalModelSlug or exact models array) is checked alongside account limits when present. Otherwise only the authenticated, unbound codex account bucket is accepted, labeled shared-account/modelQuotaVerified=false. Remaining percentage is the minimum of all applicable windows; usable headroom is max(0, remaining minus reserve), in percentage points, never a per-model allowance or token budget. Admission requires every remaining window strictly above reserve. Unknown bucket identities, stale/incomplete limits, unsupported models or credit eligibility block. Metadata must be refreshed at dispatch (60-second maximum age) and after each call. The older account-diagnostic freeQuota helper is not the selected-route admission gate. Preflight/postflight checks cannot guarantee a long in-flight call will never cross the reserve; no token-cost prediction or such guarantee is claimed.

Defaults in modelRouting: maxCallsPerTask=6, maxDeveloperCalls=3, maxReviewerCalls=3, maxEscalationsPerTask=0, allowEscalation=false, allowAstra=false, syntheticProofAuthorization=null. Task-specific settings can lower call caps or raise the reserve; all limits are bounded. At most two repair indices are accepted. A reserve/cap/missing-evidence failure never dispatches a replacement model. Synthetic CLI proofs are disabled unless an explicit expiring proof ID is configured; its persistent shared counter caps the entire proof at at most eight calls, across synthetic task IDs. This validation does not grant such authorization.

Per-task model budgets live in ignored .engineering-loop/model-budgets. A task uses its stable execution identity; bootstrap uses pinned repository/PR/base rather than transient run/nonce, so restarting bootstrap cannot refund calls. Counts are reserved durably under a lock before dispatch. Failed/interrupted calls are never refunded. Repeating the same role/HEAD/contract/policy invocation is blocked; reviewer attempts also pin commitSha and cannot re-review the same HEAD by changing repair index, policy or model. Old reviewer budgets without a recorded HEAD block for reconciliation. Escalation requires an explicit advertised model allowlist, permission, a recorded nonsecret reason, remaining budget, a higher policy tier, and a durable failed same-HEAD attempt for that role. The allowlist is empty by default. Reviewer duplicate-HEAD protection still applies to escalation. Existing persistent grant budgets and Git/status controls remain separate additional constraints, not replaced by this journal.

First review inspects the task diff and relevant callers/acceptance inputs, not an unbounded repository audit. Repair review uses a narrowed delta only when previous independent read-only REWORK, source base, contract/policy hashes, report digest, unchanged snapshot fingerprint and ancestor SHA are all verified. It passes the bound previous findings to a fresh independent reviewer; all deterministic checks still run on current HEAD and no verdict is copied. Changed contract/source/policy requires task-scope review again. A previous BLOCKED response does not qualify for delta reuse.

Receipts record task/role, requested and actually reported model, requested/observed reasoning, call/repair/escalation counters, routing reason, token input/cached/output/total when emitted, and quota before/after. Cached tokens are included within input and are not added twice. Supported turn.completed events are accumulated with turn-ID deduplication; cumulative token_count totals are a fallback, never added again. Missing usage stays null. Model identity missing/mismatched or an unapproved server reroute blocks; requested CLI arguments are never mislabeled as actual model evidence. Raw tool/model text, OAuth credentials, reset-credit IDs and account details are not logged.

Non-AI verification uses node --test with the relevant *.test.mjs files and node tools/engineering-loop/loop.mjs dry-run. Tests use fake model runners and actual isolated local Git/filesystem fixtures. Bootstrap-review, multi-proof, smoke and Codex-based E2E require separate authority; tests do not grant it. READY_FOR_SMOKE_TEST describes only verified metadata admission plus mock coverage. An authorized bounded smoke must still verify actual model identity (missing/mismatch blocks), fresh quota and an independent ephemeral session. No runtime grant is created by this document. Historical readiness remains in model-routing-readiness.json; the integration checkpoint and its explicitly authorized maximum-one-call smoke are recorded separately in adaptive-routing-integration-report.json. Rounded shared-account quota movement does not prove isolated cost or savings.
