# Smoke event observability — mock verification only

This patch does not launch a model or promote the historical BLOCKED smoke. Its missing item body/type and 158 discarded stderr bytes remain unrecoverable. No historical error text is reconstructed.

The installed CLI reports 0.153.4. The version-matched primary definition is [exec_events.rs at rust-v0.153.4](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/exec/src/exec_events.rs); the TypeScript SDK's events.ts/items.ts corroborate most types. App-server item/completed schemas are a different protocol and are not used as the exec JSONL allowlist. Rust's definition includes collab_tool_call, which the SDK item union at this tag omits; the Rust executable definition is authoritative here.

The minimal-luna-smoke profile now owns one shared parser/guard in the tracked executor. The local one-shot wrapper delegates to it instead of maintaining a second item classifier. The original wrapper is archived locally as .engineering-loop/luna-fixed-smoke-original-77ecaf2.mjs. No task/grant/expiry/checkpoint ID or replay budget was reset. No new authorization or model-executing command is introduced.

Eight event kinds are recognized: thread.started, turn.started, turn.completed, turn.failed, error, item.started, item.updated and item.completed. Only schema-shaped lifecycle events and agent_message/reasoning observations can continue. The existing body/string/usage checks and independent actual-model/acceptance gates still apply. item.updated receives the same restrictions as started/completed.

An item with type=error is recognized as a CLI error notification and conservatively stops this smoke with REPORTED_CLI_ERROR_ITEM. It is never labeled a tool and never yields PASS. Unknown events/items, malformed JSON/shapes, command_execution, file_change, mcp_tool_call, collab_tool_call and web_search stop with distinct reasons. todo_list is recognized but remains disallowed as a plan item. No tool/write/delegation category was added to the continuation allowlist.

Each decision records event.type, item.type, sorted top-level/item field names, total field counts, action and reason. Payload values, message text, thread/item IDs, commands, arguments, results and reasoning are omitted. Identifier values/keys are untrusted: invalid, token-shaped or oversized names are redacted. Shapes are limited to 32 fields and the event journal to 32 entries; the first rejection is retained separately even when the journal is full. Repeated failures stop the child once and preserve the first cause. Exit code and signal remain in the same persistent receipt.

Stderr is decoded across chunk boundaries with a 4096-character line buffer. Known errors become static safe summaries; allowlisted HTTP status, fixed error-code labels and bounded model-name mentions may be projected separately. Mentioned model names are explicitly not actual-model evidence. Unknown text is never silently dropped: omissions include source, byte count (or observed lower bound for overlong lines), reason and a sensitive-pattern flag. Non-string errors and buffer limits also have explicit omission reasons. No general arbitrary-text redactor is claimed safe; unknown payloads remain omitted. Diagnostic/omission collections are bounded.

The tracked smoke guard metadata is persisted under receipt.diagnostics.smoke; stderr summaries, safeErrorDetails and omissions are alongside it. Empty/unknown diagnostic evidence can still mean ROOT_CAUSE_UNDETERMINED. No JSON event does not prove no inference; model/effort/catalogue/request arguments do not substitute for actual identity telemetry.

Validation uses in-memory fake subprocess streams, including split chunks, final JSON without newline, valid lifecycle/item.updated, error item, unknown types, malformed JSON/shapes, exit 1, unsafe key/type labels, secret-bearing stderr and bounded logs. The real executor wiring, guard/receipt persistence and one-stop behavior are exercised with mocked metadata and spawn. See [luna-event-observability-report.json](luna-event-observability-report.json).

Luna/Sol routing, quota reserve 20%, persistent grant ledger/P1/P2, reviewer isolation, Git/SSOT and all live/merge/status-write flags are unchanged. No inference, smoke, bootstrap, multi-proof, model Reviewer, backlog, deployment, push or merge is part of this verification. A real smoke remains unverified and requires separate owner authorization; do not rerun the consumed proof.
