No audio or device settings were collected. The source before this change explicitly requested browser echo cancellation and noise suppression, and did not specify automatic gain control. That is verified source behavior. Browser/device adaptive processing is a plausible explanation for the reported level change, not a proven root cause. Existing v3 noise processing only affected the pitch-analysis copy; original playback remained unfiltered. This explains why adding that analysis filter did not clean the playback itself.

New recordings request `autoGainControl:false`, `noiseSuppression:false`, `echoCancellation:false`, and mono capture. These are best-effort requests; no hidden fallback re-enables them. The browser-reported flags from `getSettings()` are displayed in collapsed details, including UNKNOWN when absent. Only these three boolean flags are retained, never device IDs, labels or group IDs. They do not establish the state of driver/hardware processing. An already attenuated or clipped recording cannot be fully restored by the new playback filter. See the primary [AGC constraint documentation](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/autoGainControl) and [track-settings documentation](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/getSettings).

## User flow

Record a new sample: leave about half a second of background, then say one isolated syllable and stop. Original playback remains available. In **Nghe riêng đoạn đọc**, declare the initial silence only if it was actually left, then choose **Tách đoạn đọc**. An experimental amplitude-based proposal is editable. Playback contains only the selected interval; a separate checkbox toggles stationary-background reduction on that same interval when a usable reference exists. Changing boundaries/filter invalidates and revokes the previous excerpt before another can be built. Invalid/empty/reversed/out-of-bounds ranges cannot play an older excerpt.

If the start was not speech-free, leave the declaration unchecked and select boundaries manually. If no unambiguous proposal is found, no automatic excerpt is presented. Silence can still be selected explicitly; the UI does not identify that as detected speech. The waveform shows original sample amplitude with one fixed display scale. Crop controls, original duration and selected interval are visible. Native audio controls play the original or selected excerpt, pausing the other version. Nothing autoplays.

This is temporal selection with optional stationary-noise reduction, **not speaker extraction, source separation, ASR or syllable recognition**. Another person's speech/noise inside the selected range remains possible. Breathiness, low level, initial/final consonants and bursts may be missed by the proposal; the learner must listen and adjust. Qualified pronunciation assessment cannot use this selection as independent evidence.

## Processing contract

The browser decodes the retained Blob to 24 kHz mono; encoded/decoded bounds, a dedicated worker and an 8-second wall timeout apply. The worker optionally reuses [v3 spectral subtraction](acoustic-policy-v3.md) after the explicit reference declaration. Inadequate/near-zero references are disclosed as bypass; cropping remains available without filtering. Gaussian pitch conditioning is **not** applied to playback, to avoid treating a pitch-analysis low-pass copy as a voice-enhancement signal.

The proposal uses mean-removed RMS in non-overlapping 20 ms windows. With an explicit reference, search begins at 0.3 seconds and its first 15 windows provide the median noise floor; without it, the lowest 20% of all window levels provide a fallback floor. Active windows exceed `max(0.008, 3 * floor)`; nearby windows up to six indices apart merge. A candidate needs at least eight active windows and at most three seconds span. Exactly one candidate yields a proposal with 80 ms leading/100 ms trailing padding, bounded to recording edges and the declared reference end. Several adjacent syllables can merge; an energetic non-speech event can qualify. These are engineering heuristics, not a validated voice activity detector.

A selected 0.15–3.5 second interval is encoded as mono PCM16 WAV. Interior samples retain their original gain (or the selected spectral attenuation); there is no normalization, gain ramp over the utterance, compressor or AGC. Only the first/last 5 ms have a short fade to avoid cut clicks. WAV conversion clamps values to the PCM range. Cropping omits outside samples; it cannot remove overlapping sound inside a sample.

The original Blob and the optional processed WAV have separate temporary URLs. Decoded raw/filtered arrays remain only in tab memory. Reprocessing, editing, re-recording, deletion, target/route changes, backgrounding and unmount cancel work and revoke obsolete URLs. Late decode/worker results cannot publish after cancellation. The live microphone is already stopped before preparation. No microphone request occurs during processing, no upload/storage is added and no new dependency is installed.

The pitch UI below still analyses the original retained recording with its separately declared v3 noise option. A cropped playback excerpt does not silently replace pitch input, timestamps, grading, FSRS or mastery. No schema, lesson, content approval, auth, cloud, SSOT or Engineering Loop change is made.
