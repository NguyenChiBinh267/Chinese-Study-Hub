# Future phonetic evaluation gate — specification only

No recordings, consent, native references or annotations are collected or invented here. Current policy is uncalibrated; qualified review and lawful data access remain external evidence gates.

Before collecting anything, obtain explicit informed consent covering purpose, local processing, who can access recordings, retention/deletion, withdrawal and optional publication. Separate consent for recording, analysis and redistribution. Native-speaker references require a documented recording license/rights chain and qualified phonetics review; public availability and browser TTS are not sufficient. Vietnamese learner examples require the same consent protections; include differing experience levels, comfortable pitch ranges and devices/rooms. Do not infer protected traits from voice.

Define isolated tone 1–4 scope first, with allowed voiced segments, silence and consonant onsets, tone confusions, creaky/breathy voice, sustained octave errors, noise/clipping and out-of-scope connected speech/neutral tone/3+3. Keep speaker-disjoint development, calibration and held-out evaluation sets; include device-disjoint testing. Define number of participants/repetitions and power/precision requirements with competent reviewers before data collection, not retrospectively to fit results.

Use at least two independent competent Mandarin/phonetics annotators, blinded to app output. Annotate actual utterance/context, audible tone behavior and uncertainty, usable voiced boundaries, device/noise issues and reasons for abstention; never force a label. Measure raw agreement and an appropriate chance-adjusted metric with uncertainty intervals, and adjudicate disagreements independently. Correct transcription alone is not a tone-accuracy label. A qualified phonetician's label is still bounded by annotation policy, not clinical certification.

Preregister metrics: F0 error in cents against manually checked reference tracks (including octave and voiced/unvoiced errors), movement-observation confusion matrix, scope false acceptance, abstention coverage/risk curves, false reassuring feedback (false positives), false rejection (false negatives), per-speaker/device/noise results, CPU/latency/memory and confidence intervals. Keep pitch-extraction validity separate from Mandarin tone-assessment validity. Audit sampled false positives/negatives and retained unknowns; never hide abstentions in the denominator.

Set numeric release thresholds **before held-out evaluation**, approved by the competent reviewers and owner based on harms and sample uncertainty. They are intentionally not invented by this sprint: values, reviewer identities/decisions and approvals remain PENDING. Lock dataset versions, consent/rights references, algorithm/dependency/license/policy versions and analysis code before evaluating. Any policy tuning requires a new calibration round and untouched holdout. No score/mastery or authoritative diagnosis can ship merely because synthetic/browser tests pass.

Small next slice: actual Windows/secure Android capability pilot using the manual protocol, plus specialist review of the existing draft teaching material. Only after rights/consent/annotation and preregistered gates exist should a narrow F0 evaluation prototype be compared against human speech. ASR/neural systems require separate privacy, license, cost and validation review.
