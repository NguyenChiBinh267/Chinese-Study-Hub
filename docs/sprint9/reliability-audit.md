## Inspection and resulting changes

The installed Pitchy 4.1.0 MPM and local Gaussian/spectral-conditioning paths retain their existing implementation and thresholds. RMS/clipping use original samples; available F0 candidates require periodicity 0.9, the broad detector band and duration/coverage/segmentation/octave/instability checks. Median F0 from the same recording normalizes relative semitones; no fixed male/female Hz target determines whether a Mandarin tone is correct. The 50–1000 Hz detection band remains an uncalibrated engineering bound, not a universal pronunciation criterion. Existing risks remain: sustained octave ambiguity, periodic machinery, breathiness/creak, segmentation failures and adjacent syllables can fool or defeat the tracker. No threshold is relaxed on the basis of an owner sample.

New `compare-attempts.ts` only describes two successful, warning-free, finite measurements with the same target/policy/algorithm/noise-processing status. Unavailable or incompatible measurements abstain. Two rising observations with at least one semitone larger end-minus-start movement may be described as a larger measured rise; the one-semitone display distinction is an engineering heuristic, not a calibrated improvement threshold. No time warp, alignment, percentage accuracy, native-likeness, HSK proficiency, score or mastery change is added. Old raw audio is still discarded on retry; the last two numeric curves are ephemeral.

Inspection identified two feedback mismatches: a long detected nucleus used the same unsupported-target message as an unsupported note, and unstable tracking fell through to generic advice despite a specific warning. Their copy now describes the measured scope/instability without claiming multiple syllables or an articulation error. The three headings explicitly distinguish what was observed, one practice action and retry. Existing notes/SVGs supply Xem cách sửa / Xem khẩu hình; static anatomy instructions remain labeled unreviewed guidance, never an inference from the recording. Technical detail and partial/previous-graph explanations stay available.

## Live input level and lifecycle

A new optional browser port reads a 1024-sample time-domain AnalyserNode about ten times per second while recording. Peak/RMS are level observations, not SNR, verified speech, probability or phonetic score. Its output is not connected to speakers; the primary [AnalyserNode documentation](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode) confirms that analysis works with an unconnected output. No MDN example code/assets were copied. Existing best-effort capture requests remain AGC/NS/AEC off, with the three whitelisted getSettings flags displayed separately. Driver/device processing can remain unknown.

The meter uses the existing stream and never calls getUserMedia itself. Stop/cancel/error/limit/unmount releases its RAF, disconnects nodes and closes the AudioContext before stopping tracks. Partial setup failure also closes the context, while lack of level-meter support does not prevent recording. A failure-path regression verifies that a throwing meter cleanup cannot prevent physical tracks from being stopped. Worker timeout, decoding limits, generation isolation, recording cleanup and selected WAV playback remain in regression. The selected playback crop is not substituted into the pitch engine.

## Pilot evidence and privacy

The pilot is optional at `/learn/pronunciation?pilot=1`. It caps recording attempts at three per supported target in the current tab and requires original playback to reach the end before analysis. This listen gate does not prove human attention. Local report fields are owner-entered; unknown/virtual/synthetic sources cannot produce hardware PASS. Changing device/source resets the report; monotonic attempt IDs prevent a late old result from attaching to a new source's row. Permission failure, unknown graph match and confusing feedback stay explicit. Earlier attempts remain editable.

JSON export contains metadata, peak level, scalar measurement summaries, warnings and owner observations. It contains no Blob, PCM samples, encoded voice or full frame curve. Download is an explicit user action to their machine; no upload, server learning write, localStorage or IndexedDB is added. Audio remains in the existing temporary tab lifecycle. Exported owner reports are not a consented speech corpus or independent phonetic evaluation.

Canonical task status, Engineering Loop, PR #5/#6, notes, illustrations, lesson packages, PostgreSQL schema/RLS/idempotency, grading, FSRS, mastery, planner and production lockout stay outside this change. No ASR, LLM, paid service, cloud project or dependency upgrade. Hardware and competent-language evidence cannot be manufactured by automated tests.
